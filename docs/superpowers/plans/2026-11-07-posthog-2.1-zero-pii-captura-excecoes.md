# PostHog 2.1 — Blindagem Zero-PII e Captura Central de Exceções — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fechar os vetores de PII/credencial existentes e ligar todo erro de service, query, render e exceção não tratada dos 7 apps ao PostHog Error Tracking, com payload sanitizado.

**Architecture:** O core ganha um ponto único de reporte (`reportException` em `services/analytics.ts`) que recebe `unknown`, descarta erro esperado, converte o erro num `Error` sem PII (`toReportableError`) e entrega ao adapter. `handleServiceError` e o `QueryCache`/`MutationCache` chamam esse ponto; um `WeakSet` impede duplicata quando o mesmo erro passa pelos dois. Web e mobile só trocam o SDK por trás do adapter: `createPostHogBrowserAdapter` (já existe) e `createPostHogNativeAdapter` (novo, também no core, estrutural, sem dependência de SDK).

**Tech Stack:** `posthog-js@1.425.1` (`captureException`, `capture_exceptions`, `before_send`), `posthog-react-native@4.66.3` (`captureException`, `errorTracking.autocapture`, `before_send`, `personProfiles`), Next.js 16 App Router (`error.tsx`/`global-error.tsx`), Zod 3.23.8, Jest/ts-jest (core), jest-expo (mobile, mobile-client).

**Spec:** `docs/analise-2-posthog-proativo-erros.md` — Plano de Ação 2.1 (e o diagnóstico das seções 2.1/2.2).

### Task 3: Sanitização de erro, metadado e URL (puro, sem SDK)

**Files:**

**Interfaces:**
- Consumes: `getErrorType`, `getErrorCode`, `getErrorStatus`, `isPostgrestError`, `isAuthError` (Task 2).
- Produces:
  ```ts
  export interface SafeErrorMetadata {
    method?: string;
    errorType?: string;
    code?: string;
    status?: number;
    fingerprint?: readonly string[];
    componentStack?: string;
    recordId?: string;
  }
  export const EXPECTED_AUTH_CODES: readonly string[]; // ['invalid_credentials', 'invalid_grant', 'otp_expired']
  export const SENSITIVE_URL_PARAMS: readonly string[]; // ['access_token','refresh_token','provider_token','provider_refresh_token','code','token','token_hash','email']
  export const URL_PROPERTY_KEYS: readonly string[];    // ['$current_url','$referrer','$initial_referrer','$initial_current_url','$session_entry_url','$prev_pageview_pathname']
  export function isExpectedError(error: unknown): boolean;            // AbortError ou AuthError com code em EXPECTED_AUTH_CODES
  export function buildSafeErrorMetadata(error: unknown, method?: string): SafeErrorMetadata;
  export function toReportableError(error: unknown): Error;
  export function redactMessage(message: string): string;
  export function sanitizeUrl(url: string): string;
  export function sanitizeCaptureEvent<T extends { properties?: Record<string, unknown> }>(event: T | null): T | null;
  ```

Regras de `toReportableError` (o `name` é preservado, a mensagem é reconstruída):
- `ZodError` → `name = 'ZodValidationError'`, mensagem `issues.slice(0, 5).map(i => \`${path}:${i.code}\`).join('; ')`, em que `path` troca índice numérico por `*` (`[3,'phone']` → `*.phone`).
- Postgrest → `name = 'PostgrestError'`, mensagem `Postgrest ${code}`.
- AuthError → `name = 'SupabaseAuthError'`, mensagem `Auth ${code ?? status ?? 'unknown'}`.
- Storage → `name = 'SupabaseStorageError'`, mensagem `Storage ${status ?? 'unknown'}`.
- Outro `Error` → mesmo `name`, mensagem `redactMessage(error.message)`.
- Não-`Error` → `new Error('UnknownError')` com `name = 'UnknownError'`.
- `stack`: quando o original tem `stack` string, a primeira linha é trocada por `${name}: ${mensagemSegura}` e o resto é mantido; senão fica o stack do `Error` novo.

`redactMessage` substitui e-mail → `[email]`, sequência de 8+ dígitos (com ou sem pontuação de CPF/CNPJ/telefone) → `[number]`, JWT (`eyJ` + base64url com dois pontos) → `[token]`. `sanitizeUrl` remove o hash inteiro e os parâmetros de `SENSITIVE_URL_PARAMS`, preserva o resto; string que não é URL absoluta nem path começando com `/` volta sem alteração. `sanitizeCaptureEvent` devolve cópia com cada chave de `URL_PROPERTY_KEYS` que for string passada por `sanitizeUrl`; `null` → `null`.

- [ ] **Step 1: Testes** (`error-reporting.test.ts`):
  - `toReportableError(zodErrorDeEnum)` → `message` não contém o valor recebido (`'segredo@x.com'`) e é `'status:invalid_enum_value'`.
  - Postgrest `{ message: 'duplicate key ... (email)=(a@b.com)', details: 'Key (email)=(a@b.com)', hint: '', code: '23505' }` → `message === 'Postgrest 23505'`, `stack` não contém `a@b.com`.
  - `new Error('falhou para joao@x.com')` com stack original → `message === 'falhou para [email]'` e `stack.split('\n')[0] === 'Error: falhou para [email]'`.
  - `redactMessage('cpf 123.456.789-09 tel 11987654321 jwt eyJa.eyJb.c')` não contém nenhum dos três valores.
  - `sanitizeUrl('https://x.com/client/login?next=%2Fevents&code=abc#access_token=t&refresh_token=r')` → `'https://x.com/client/login?next=%2Fevents'`; `sanitizeUrl('/app/event/1')` inalterado.
  - `sanitizeCaptureEvent({ event: '$pageview', properties: { $current_url: 'https://x.com/?token=1', foo: 'https://x.com/?token=1' } })` → só `$current_url` limpo; `foo` intocado.
  - `isExpectedError` → `true` para AbortError e AuthError `otp_expired`; `false` para Postgrest `42501`.
  - `buildSafeErrorMetadata(postgrest42501, 'favorites.add')` → `{ method: 'favorites.add', errorType: 'PostgrestDatabaseError', code: '42501' }` (sem `status`).
